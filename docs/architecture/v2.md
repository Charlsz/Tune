# Tune — Arquitectura v2 (aplicación EO)

**Fecha:** 2026-09-21 · **Decisión:** [ADR 005](../decisions/005-app-inferencia-checkpoints-publicados.md) ·
**Anterior:** [v1](./v1.md) (laboratorio de fine-tuning, ahora secundario)

## Qué hace

GeoTIFF satelital → modelo Prithvi‑EO 2.0 publicado (inundación o incendio) → máscara
georreferenciada + estadísticas → mapa web con historial.

```text
 web (Vite+React+Leaflet)  ──/api──▶  eo-api (FastAPI)  ──▶  AnalyzeUseCase
        :8080 nginx                      :8000                  │
                                                                ├─ HazardSegmenter  → PrithviSegmenter (TerraTorch, pesos HF)
                                                                └─ AnalysisRepository → FileAnalysisRepository (artifacts/analyses/<id>/)
```

## Capas (misma clean architecture de v1)

| Capa | Nuevo en v2 | Reutilizado |
|---|---|---|
| `domain/` | `analysis.py` (HazardTask, Analysis, SegmentationOutput, GeoBounds); puertos `HazardSegmenter`, `AnalysisRepository` | entidades y puertos del lab |
| `application/` | `analyze.py` (`AnalyzeUseCase`, `compute_stats`) | `stages/*` |
| `infrastructure/` | `inference/prithvi.py`, `analyses/filesystem.py` | `container.py`, settings, training, tracking |
| `interfaces/` | router `/api` (`analyses.py`), `tune analyze` | FastAPI app, CLI Typer, `/health` |
| `web/` | Frontend completo | — |

Dependencias hacia adentro se mantienen: el dominio no conoce numpy/torch (la máscara viaja como
`Any`); TerraTorch, rasterio y PIL solo aparecen en infraestructura y con import perezoso.

## Endpoints

| Método | Ruta | Descripción |
|---|---|---|
| GET | `/api/tasks` | Tareas disponibles y su modelo HF |
| POST | `/api/analyze` | multipart `file` (GeoTIFF) + `task` → análisis |
| GET | `/api/analyses` | Historial (más reciente primero) |
| GET | `/api/analyses/{id}` | Un análisis |
| GET | `/api/analyses/{id}/{artifact}` | `mask_png`, `preview_png`, `mask_tif`, `input` |

## Artefactos por análisis

`artifacts/analyses/<id>/`: `analysis.json`, `input.tif`, `mask.png` (RGBA para el mapa),
`preview.png` (RGB de la imagen), `mask.tif` (GeoTIFF uint8, nodata 255).

## Despliegue

`docker compose --profile app`: `eo-api` (imagen `docker/training/Dockerfile`: torch + terratorch +
GDAL; CPU por defecto, GPU con `docker-compose.gpu.yml`) y `web` (nginx sirviendo el build de
Vite y proxeando `/api`). Volumen `hf-cache` persiste los pesos (~1.2 GB por modelo).

## Entradas aceptadas

GeoTIFF con las 6 bandas Prithvi (BLUE, GREEN, RED, NIR_NARROW, SWIR_1, SWIR_2) o, para
inundaciones, un Sentinel‑2 L1C completo (se seleccionan las bandas 2,3,4,8A,11,12). Sin CRS la
máscara se calcula pero no se ubica en el mapa.

## Fuera de alcance (por ahora)

PostGIS, autenticación, cola de trabajos, descarga automática de imágenes Copernicus.
